# Setting up the bibliography search site

This zip contains a Jekyll site to add to your existing `bibliographies`
repo, alongside your `.bib` files. It does **not** touch or replace your
`.bib` files, `README.md`, or `LICENSE` — everything here is new.

## 1. Copy the files in

Unzip this into the root of your local `bibliographies` checkout, so you
end up with (among your existing files):

```
bibliographies/
├── biblio4-utf8.bib          (already there)
├── mbh-vols.bib               (already there)
├── README.md                  (already there)
├── _config.yml                 (new)
├── _layouts/default.html       (new)
├── index.html                  (new)
├── about.md                    (new)
├── assets/css/style.css        (new)
├── assets/js/app.js             (new)
├── scripts/build_bibliography.py (new)
├── requirements.txt             (new)
└── .github/workflows/build-and-deploy.yml (new)
```

## 2. Add two lines to your `.gitignore`

The bibliography JSON that the search page reads is generated by the
build script (and regenerated automatically by GitHub Actions on every
push), so it doesn't need to live in git. Add these two lines to your
existing `.gitignore`:

```
assets/data/bibliography.json
_site/
```

(This zip includes an already-built `assets/data/bibliography.json` so
the site works immediately if you preview it locally — see step 4 — but
there's no need to commit it.)

## 3. Commit and push

```
git add .
git commit -m "Add Jekyll search site"
git push
```

## 4. Enable GitHub Pages

In the repo on GitHub: **Settings → Pages → Build and deployment → Source**,
select **GitHub Actions** (not "Deploy from a branch"). The workflow in
`.github/workflows/build-and-deploy.yml` will then run automatically:
it regenerates the JSON from your `.bib` files and deploys the site.
The first run starts as soon as you push; check the **Actions** tab for
progress. Once it succeeds, the site will be live at
`https://wujastyk.github.io/bibliographies/`.

From then on, any time you edit `biblio4-utf8.bib` (or `mbh-vols.bib`)
and push, the site rebuilds and updates automatically within a minute or
two — no separate step needed.

## Previewing locally (optional)

If you want to see changes before pushing:

```
pip install -r requirements.txt
python3 scripts/build_bibliography.py   # regenerates assets/data/bibliography.json
bundle exec jekyll serve                # needs Ruby + the jekyll gem installed
```

then open `http://localhost:4000/bibliographies/`.

## If you rename the repo, or add a custom domain

`_config.yml` has `baseurl: "/bibliographies"`, which assumes the site
stays at `github.com/wujastyk/bibliographies` and is served at
`wujastyk.github.io/bibliographies/`. If you rename the repo or point a
custom domain at it, update `baseurl` (and `url`) in `_config.yml`
accordingly.

## Adding another bibliography file later

If you ever want a third `.bib` file included (say, a separate
collection), add a line to the `SOURCES` list near the top of
`scripts/build_bibliography.py`:

```python
SOURCES = [
    ("biblio4-utf8.bib", "main", "Main bibliography"),
    ("mbh-vols.bib", "mahabhasya-volumes", "Patañjali's Mahābhāṣya (Joshi & Roodbergen volumes)"),
    ("your-new-file.bib", "your-tag", "Label shown in the Collection filter"),
]
```

No other changes needed — the search page picks up new collections and
entry types automatically.
